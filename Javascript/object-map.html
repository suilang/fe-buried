Object 和 Map 的区别 ​

前言 ​

本文整理了 Object 和 Map 两种数据结构的区别，以及 Map 的时间复杂度分析，帮助理解在面试中常见的问题。

一、Object ​

1.1 定义 ​

Object 是 JavaScript 的一种数据类型，用于存储各种键值集合和更复杂的实体。可以通过 Object() 构造函数或者使用对象字面量的方式创建对象。

javascript
const obj = new Object() // 得到一个空对象 {}
const obj2 = {} // 得到一个空对象 {}
1
2

1.2 特点 ​

  • 以键值对的形式存储数据
  • 键（key）必须是 String 类型或 Symbol 类型，其他类型会自动转换成 String 类型
  • 属性值可以是任何类型的数据，包括基本类型、对象类型和函数类型

1.3 Object 方法 ​

1.4 删除键值对 ​

Object 中并没有提供方法删除键值对，需要使用 delete 运算符：

javascript
let obj = {
    name: '张三',
    age: '100'
}
delete obj.name // true
// 或者
delete obj['name'] // true
console.log(obj) // {age: 100}

二、Map ​

2.1 定义 ​

Map 也是以键值对形式存储数据的，它的键（key）可以是任意类型，是一种更加完善的 Hash 结构实现。创建 Map 结构通常使用 new Map() 来实现。

javascript
const map = new Map()
map.set(1, 2)
console.log(map) // Map(1) {1 => 2}
map.get(1) // 2
map.has(1) // 查看是否有该键值 true

2.2 注意事项 ​

设置对象属性同样适用于 Map 对象，但容易造成困扰，因此并不推荐这样做：

javascript
const map = new Map()
map['a'] = 1
console.log(map) // Map(0) {a: 1, size: 0}
map.get('a') // undefined
map.has('a') // false

这种设置属性的方式不会改变 Map 的数据结构，它使用的是通用对象的特性。'a' 的值未被存储在 Map 中，无法被查询到，因此 Map 的 size 属性是 0。

2.3 Map 键的唯一性 ​

Map 的键（key）具有唯一性，确定后再次创建会覆盖。Map 的键实际上是跟内存地址绑定的，只要内存地址不一样，就视为两个键：

javascript
const map = new Map();
// 使用数组作为 Key，获取值时返回 undefined
// 因为这是一个引用数据类型，设置的和获取的并不是同一个引用地址
map.set(['a'], 555);
map.get(['a']) // undefined

const k1 = ['a'];
const k2 = ['a'];
map.set(k1, 111).set(k2, 222);
map.get(k1) // 111
map.get(k2) // 222

2.4 将 NaN 作为 Map 的键 ​

NaN 也可以作为键。虽然 NaN 与任何值甚至与自己都不相等（NaN !== NaN 返回 true），但是因为所有的 NaN 的值都是无法区分的：

javascript
const map = new Map()
map.set(NaN, "not a number")
map.get(NaN) // "not a number"
const otherNaN = Number("foo") // NaN
map.get(otherNaN) // "not a number"

2.5 Map 的迭代 ​

由于 Map 内置有迭代器 iterator，因此可以使用 forEach 和 for of 实现迭代，迭代的顺序按插入的顺序进行。

四、Map 的时间复杂度 ​

4.1 基本回答 ​

Map 的查找时间复杂度：

  • 最好情况：O(1)
  • 最坏情况：O(n)

4.2 详细解释 ​

Map 的时间复杂度主要取决于其具体实现方式（哈希表）：

  1. 理想情况（O(1)）：如果能够将键均匀分布在整个哈希表中，避免冲突，那么 Map 的查找、插入和删除操作的时间复杂度可以达到 O(1)，即常数时间复杂度。

  2. 冲突情况：

    • 如果哈希函数导致很多键落在同一个桶中，形成链表，时间复杂度将退化为 O(n)，其中 n 是链表中的条目数量
    • 如果形成红黑树，时间复杂度为 O(log n)

4.3 面试回答建议 ​

面试官：请说下知道了键，在 Map 中查找值的时间复杂度是多少？

回答：有可能是 O(1)，也有可能 O(n)。

面试官：那在什么情况下时间复杂度为 O(1) 呢？

回答：在 Map 的结构简单没有冲突的时候，因为这样的话需要的键值直接在 Map 的第一层，不需要遍历就可以找到准确的值。反之，如果哈希冲突严重，就可能造成 O(n) 的情况。

五、总结 ​

  1. Object 和 Map 都是键值对存储结构，但在键的类型、迭代方式、操作方法等方面有显著差异
  2. Map 提供了更完善的 Hash 结构实现，键可以是任意类型
  3. Map 的时间复杂度取决于哈希表的实现和冲突情况，理想情况下为 O(1)
  4. 在实际开发中，应根据具体场景选择合适的数据结构：
    • 需要字符串或 Symbol 作为键，且需要 JSON 序列化时，选择 Object
    • 需要任意类型作为键，需要保持插入顺序，或需要频繁增删键值对时，选择 Map

六、Map 的底层实现原理 ​

6.1 JavaScript 中 Map 的实现 ​

Map 是一个数据结构，保存了 key-value（键值对），每个键映射到一个值，Map 可以按照元素插入的顺序进行遍历。

在 JavaScript 中，Map 是由哈希表（HashMap） 实现的，但不同引擎的具体实现有所不同。

6.2 V8 引擎中的 Map 实现 ​

在 V8 引擎（Chrome 和 Node.js 使用）中，Map 使用了一种称为 OrderedHashMap 的数据结构：

核心特点：

  • 使用两个内部数组：一个用于存储键值对（entries），一个用于哈希索引
  • 保证了 O(1) 的平均查找时间
  • 严格保持插入顺序，这是通过链表结构实现的
  • 支持任意类型的键，包括对象、函数、NaN 等

为什么 Map 能保持插入顺序？

V8 中的 Map 在存储键值对时，除了维护哈希表用于快速查找外，还维护了一个链表结构来记录插入顺序。每次插入新元素时，都会在链表末尾添加该元素，这样在遍历时就可以按照插入顺序输出。

6.3 哈希表的基本结构 ​

哈希表通常由数组 + 链表的形式组成，综合了两者的优势：

  • 数组：提供 O(1) 的随机访问能力
  • 链表：处理哈希冲突，将哈希值相同的元素串联起来

6.4 哈希函数的设计原则 ​

哈希函数的设计相当重要，需要考虑以下内容：

设计原则说明
均匀分布好的哈希函数会使得键在哈希表中的分布尽可能均匀，任何小的改动都会产生一个完全不同的哈希值，最大程度减少哈希冲突
计算效率哈希函数的计算过程应该尽可能高效，以便能在 O(1) 时间内完成键到索引的映射
不可逆性哈希函数应该是单向的，即从哈希值无法还原出原始的输入数据，保护数据的安全性
可扩展性哈希函数应该能够适应不同规模的数据集，无论是小型还是大型数据集，都能够保持较好的性能

6.5 Map 的 set 过程 ​

Map 的 set 过程：

  1. 首先计算 key 的 hash 值
  2. 根据 hash 值计算在数组中的索引位置
  3. 如果数组在该位置有值，则通过比较是否存在相同的 key
    • 若存在则将新的 value 覆盖原来的 value
    • 不存在则将该 key-value 添加到链表中
  4. 若数组在该处没有元素，则直接保存
  5. 同时维护插入顺序链表

6.6 Map 的 get 为什么是 O(1) ​

Map 在寻找指定的 key 时，会先计算 key 的 hash 值，随后根据 hash 值搜索在数组中的索引位置。

通过 index = hash % capacity 可以直接定位到数组位置，相关的 value 会直接存储在该位置或对应的链表中。

时间复杂度分析：

  • 理想情况（O(1)）：当哈希函数能够将键均匀分布，没有冲突或冲突很少时
  • 最坏情况（O(n)）：当所有键都哈希到同一个位置，形成长链表时
  • 实际情况：通过良好的哈希函数设计和动态扩容机制，通常能保持 O(1) 的平均时间复杂度

6.7 Map 的扩容机制 ​

Map 在创建时会有初始容量，随着元素的增加，当达到一定负载因子（load factor）时会触发扩容：

扩容过程：

  1. 创建一个新的更大的数组
  2. 重新计算所有元素的 hash 值
  3. 将元素重新分配到新数组中
  4. 更新内部数据结构

JavaScript 引擎的优化：

  • 初始容量和扩容策略由引擎内部决定，不需要开发者关心
  • 现代引擎会根据实际使用情况动态调整，以平衡内存使用和性能

6.8 大数据扩容的优化策略 ​

在面对大量数据时，哈希表的扩容可能成为性能瓶颈，常见的优化策略包括：

优化策略说明
渐进式扩容不一次性完成所有数据迁移，而是在每次操作时迁移一部分数据，分散扩容压力
预分配空间如果能预估数据量，可以提前设置较大的初始容量，避免频繁扩容
并发扩容在多线程环境下，将扩容任务分解并在多个处理器上并发执行
选择合适的负载因子调整负载因子来平衡空间利用率和查找效率

6.9 Map 为什么有序？ ​

JavaScript 的 Map 与传统的哈希表不同，它严格保持插入顺序，这是因为：

  1. 规范要求：ECMAScript 规范明确要求 Map 必须按照插入顺序进行迭代
  2. 实现方式：V8 引擎通过维护一个额外的链表来记录插入顺序
  3. 内存开销：为了保持顺序，Map 需要额外的内存来维护链表结构

七、面试常见问题 ​

7.1 Map 是如何实现有序的？ ​

Map 在内部维护了一个链表结构来记录元素的插入顺序。每次插入新元素时，除了在哈希表中存储键值对外，还会在链表末尾添加该元素。遍历时，按照链表的顺序输出，从而保证了插入顺序。

7.2 Map 最坏查找情况是怎样的？ ​

  • 最坏情况：O(n)，当所有键都哈希到同一个位置，形成长链表时
  • 实际情况：通过良好的哈希函数设计和动态扩容，通常能保持 O(1) 的平均时间复杂度

7.3 为什么 Map 的键可以是任意类型？ ​

Map 使用 SameValueZero 算法来比较键的相等性：

  • 对于原始类型（number、string、boolean 等），比较值是否相等
  • 对于引用类型（对象、数组、函数等），比较引用地址是否相同
  • 特别地，NaN 被视为等于 NaN（这与 === 不同）

这种设计使得 Map 可以使用任意类型的值作为键。

7.4 Map 过大时，扩容怎么做？怎么优化性能？ ​

扩容过程：

  • 创建一个新的更大的数组
  • 将原数组中的所有元素重新计算 hash 值，重新分配到新数组中

优化策略：

  1. 预估容量：如果能预估数据量，可以提前创建足够大的 Map
  2. 避免频繁增删：频繁的增删操作会导致内存碎片
  3. 选择合适的数据结构：如果不需要保持顺序，可以考虑使用普通对象（键为字符串时）
