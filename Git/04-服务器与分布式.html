服务器上的 Git / 分布式 Git / GitHub 总结 ​

本章总结第4-6章的重点内容：Git 服务器协议、分布式协作模式和 GitHub 使用。

1. 服务器上的 Git（第四章） ​

Git 协议 ​

Git 支持四种传输协议：

协议特点适用场景
本地协议通过文件系统共享团队共享同一文件系统
HTTP(S)智能协议，支持授权最流行，易于使用
SSH安全，需要 SSH 访问需要授权的读写访问
Git 协议速度快，无授权大型只读项目

本地协议 ​

bash
# 克隆本地仓库
git clone /srv/git/project.git

# 添加远程仓库
git remote add local_proj /srv/git/project.git

3. GitHub（第六章） ​

账户配置 ​

创建账户 ​

  1. 访问 github.com
  2. 注册用户名、邮箱、密码
  3. 验证邮箱

SSH 密钥配置 ​

bash
# 生成密钥
ssh-keygen -t ed25519 -C "your@email.com"

# 添加到 SSH Agent
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# 在 GitHub 添加公钥
cat ~/.ssh/id_ed25519.pub
# 复制添加到 GitHub → Settings → SSH and GPG keys

对项目做出贡献 ​

原始仓库 → Fork → 本地修改 → Pull Request → 审核 → 合并

管理组织 ​

组织概念 ​

组织 → 团队 → 成员 → 仓库
1
  • 组织：管理多个仓库和团队
  • 团队：按功能或项目分组
  • 成员：组织成员
  • 仓库：项目代码

创建组织 ​

  1. 点击 "+" → "New organization"
  2. 选择免费计划
  3. 输入组织名称
  4. 邀请成员

团队权限 ​

  • Owner：完全控制
  • Admin：管理仓库设置
  • Write：推送和合并
  • Read：读取和克隆

4. 总结 ​

服务器部署要点 ​

  1. 选择合适的协议（HTTP/S 或 SSH）
  2. 创建裸仓库 --bare
  3. 配置 SSH 公钥认证
  4. 考虑使用第三方托管服务简化运维

分布式协作要点 ​

  1. 选择适合团队规模的工作流
  2. 建立提交规范（conventional commits）
  3. 使用 Pull Request 进行代码审核
  4. 定期同步上游仓库

GitHub 使用要点 ​

  1. 启用 SSH 密钥和 2FA
  2. 使用 Fork + PR 贡献开源
  3. 利用组织管理团队
  4. 使用 GitHub CLI 提高效率
  5. 配置分支保护规则

推荐工作流 ​

1. Fork 仓库（开源）或 克隆（内部）
2. 添加上游仓库
3. 创建功能分支
4. 开发并提交
5. 推送并创建 PR
6. 等待审核
7. 合并后删除分支
8. 同步上游更新
